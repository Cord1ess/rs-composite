01Verdict

Strong bones, three real hazards, one dead optimization, and a class that outgrew its file.

The foundations from the first audit have held up: worker-isolated rendering, single-channel R8 texture packing, solved-not-guessed framing constants, the measurement-first workflow, and now a tuning system where every visual parameter flows from one schema. None of that needs revisiting.

What the last three weeks of fast iteration left behind: the failure paths were never finished (a texture that fails twice, or a blocked worker, currently strands a black hero with no fallback), the idle-skip optimization is silently dead (the cloud drift marks every frame dirty, so the GPU renders at display rate forever, everywhere), and earth-scene.ts hit 1,059 lines â€” a motion controller, a resolution governor, an asset loader, three materials, a marker projector and a tuning bus sharing one class. Each is small and clean on its own; together they are why every change now touches the same file.

The plan below is ordered so safety lands first, the perf floor second, and the pure refactor third â€” with a golden-frame harness making "zero visual change" a checked property instead of a hope.

03Flaws & issues

Everything found, ordered by what it costs. File references are to the shipped code at 624453e.

Resilience

F1 Texture failure strands a black hero critical

earth-scene.ts:270 fires void this.load(). If any of the four fetches fails twice (one retry is the whole policy), the Promise.all rejection is swallowed, onReady never fires, the loading screen gives up at MAX_WAIT and reveals a hero containing only the galaxy CSS. The capability-gate fallback image never engages â€” it only guards the probe, not the load.

Fix: wrap load(); on terminal failure post a new error protocol message â†’ Earth3D tears down the canvas, mounts the same hero-fallback.webp backdrop GlobeField uses, and calls markHeroReady() so the loader lifts on time. Wire onShaderError into the same path: a compile failure today logs loudly and shows nothing.

F2 Worker construction is uncaught high

Earth3D.tsx calls new Worker(â€¦) and transferControlToOffscreen() bare. A CSP with worker-src restrictions, an extension interfering, or an exotic embedder throws synchronously â€” the whole effect dies and no globe and no fallback renders, even though a perfectly good main-thread path sits in the else branch.

Fix: try/catch around worker creation + transfer; on failure, fall through to the main-thread scene path. Three lines, an entire class of environment failures absorbed.

F4 The fallback image shows a dead design high

public/textures/hero-fallback.webp was baked before the blue rebrand, the cloud shell, and the entire lighting arc. Every gated visitor (data-saver, 2 cores, no WebGL â€” a real slice in the export markets) sees a planet that no longer exists, and F1's fix will send failures there too.

Fix: regenerate from a headless capture of the finished, tuned globe; add a npm run fallback script so it can never silently go stale again after future tuning.

Performance

F3 The idle skip is dead â€” the GPU never rests high

The cloud drift sets needsDraw = true every frame whenever motion is allowed, and motion is now always allowed. The carefully built dirty-check renders every frame at display rate in both states, forever. But the drift it is repainting for moves the deck at ~1.7 px/s in the showcase â€” a 60 Hz repaint of a 2 px/s phenomenon.

Fix: an adaptive draw cadence in place of the boolean: display-rate while interacting, touring or scrubbing; ~8 Hz while parked with only drift alive; 0 when the tab is hidden or the hero is off-screen (already handled). Same visual result, roughly 85% fewer parked-state frames â€” this is the battery of every laptop that sits on the section view.

F5 Marker messages at 60 Hz for a static picture medium

reportMarkers posts a six-object structured clone every drawn frame; the change-detection that would suppress identical frames lives on the receiving side (Earth3D.applyMarkers write dedup). The message itself is the cost.

Fix: move the per-marker delta check (Â±0.5 px) into the worker and post only changed frames. Parked showcase â†’ zero messages.

F6 Pointer moves forwarded unthrottled low

Every pointermove posts to the worker â€” 120â€“240 Hz on high-rate mice and pens, all but one per frame wasted since the scene only integrates the latest x.

Fix: coalesce to one message per animation frame in Earth3D.

F16 Bicubic land sampling runs at the ball view too medium

The 4-tap B-spline reconstruction exists to fix magnification blur at the entry crop. In the showcase the land texture is minified â€” bicubic adds nothing there but still costs 4 taps on every fragment, every frame (and F3 made that every frame literal).

Fix: branch on fwidth(vUv): texel footprint â‰¥ 1 screen pixel â†’ single bilinear tap. Spatially coherent branch, near-zero divergence cost, âˆ’3 taps across the whole disc in the state the page spends most of its life in.

F14 Cloud shell pays full price over clear sky medium

Roughly half the shell's fragments are clear ocean, but all five taps and the full lighting path run before the alpha test discards them.

Fix: early-out after the first (deck) tap when cl sits safely below every threshold that could produce coverage â€” veil included via a conservative margin. Saves ~4 taps on ~half the shell's area.

F15 The halo blends 2.5 radii of mostly-nothing medium

Letting the light spread (correct call) made the quad huge; at the entry crop it covers most of the viewport, and every fragment pays the blend stage even where the compressed alpha is far below one display step.

Fix: if (aC < 0.002) discard; after compression â€” skips raster output on the dead area while the visible gradient (protected by the dither) is untouched.

F17 Anisotropy 8 on the 6K lights map low

The lights texture is the largest resource in the scene and is sampled twice per fragment with aniso 8 â€” up to 8 sub-samples per tap at exactly the grazing angles the whole cap sits at. City dots survive aniso 4 visually.

Fix: trial aniso 4 for the lights map only, golden-frame diff to confirm; keep 8 for land where coastline crispness is the point.

Structure

F10 earth-scene.ts is a 1,059-line god class medium

Motion state machine (drag, seek, tour, blend), resolution governor, frame-time EMA, asset pipeline, three material definitions, marker projection, tuning application and the halo builder in one class. Every feature request for a month has patched this file; review diffs are getting long and constants for one concern sit next to another's.

Fix: the module split in Â§05. Composition root stays ~250 lines; each concern gets a file, a surface and its own comments.

F8 Duplicated uniform state across materials medium

uCloudShift is written to two materials by hand every frame; uSun lives in two materials plus a third derived uSunDir; uTermLo/Hi, uCloudAmt exist twice. setTune papers over it, but the sync is discipline, not structure â€” the cloud/shadow lockstep bug class exists because of this.

Fix: build one shared uniform table from TUNE (sky-state.ts) and hand the same { value } object references to every material that declares the name. One write, everywhere, by construction. three.js supports shared uniform objects natively.

F7 uLandTexel hardcodes the bake resolution low

{ value: new Vector2(1/5120, 1/2560) } â€” change SIZES in the bake script and the bicubic filter silently degrades with no error anywhere.

Fix: set it from bitmap.width/height at load time; delete the constant.

F9 The resolution governor only ratchets down low

Sticky-for-the-session was the right anti-thrash call, but a laptop that briefly thermal-throttled (or ran on battery for a minute) is stuck at 1.25Ã— until reload.

Fix: one upward probe per session after 30 s of sustained <12 ms frames; revert within 250 ms if the probe fails. Bounded, thrash-free.

F12 TunePanel ships in the production bundle low

Runtime-gated but always parsed on the home page (~9 kB + schema).

Fix: check the gate first, then import() the panel body on demand.

F11 No motion escape hatch remains low

Ignoring prefers-reduced-motion was the right product call (Windows performance mode lies), but it removed the only brake genuinely motion-sensitive visitors had.

Fix (later, cheap): a small "pause motion" control in the footer or dock that flips the scene's motion flag at runtime. Not urgent; noted so it isn't forgotten.
